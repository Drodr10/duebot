DueBot: a Discord bot that knows when your Canvas work is due

Follow this top to bottom. Each step has a "Show me the code" toggle. Try it first, peek second. In the repo, git checkout start is what we build from and git checkout main is the finished bot.

Before we start

Tick these off. Takes about 10 minutes. Everything here happens in a browser.

Careful. Never paste your token or your feed URL into Discord, a commit, or a screenshot. .env is gitignored for exactly this reason.

1. Bring it online

First, the preflight. It checks each value in .env, asks Discord whether the token is real, and downloads your Canvas feed, and it tells you exactly which one is wrong.

python check.py

When it says all good:

python bot.py

You should see Logged in as YourBot#1234. In Discord, type /ping. If the command doesn't show up, press Ctrl+R (Cmd+R on Mac) to reload Discord.

What just happened. Your code opened one long-lived connection to Discord, called the Gateway. It's a WebSocket: unlike a normal HTTP request, it stays open, and Discord pushes events down it. Your bot never asks "anything new?". Set SHOW_GATEWAY=1 in .env and restart to watch the heartbeats that keep that connection alive.

Intents. When the bot connects it tells Discord which kinds of events it wants. We use the defaults: server info and voice state. We do not ask for message content, which is why there was no scary toggle in the portal. Slash commands arrive as their own event type.

2. Step 1: know when a friend joins voice

Discord sends an on_voice_state_update event every time anyone joins, leaves, mutes or moves. Write a handler that DMs you when one specific person goes from no channel to a channel. Find the STEP 1 comment in bot.py.

Hints: before.channel is None and after.channel is not None means "just joined". await bot.fetch_user(OWNER_ID) gets you; await owner.send("...") DMs you.

Show me the code
@bot.event
async def on_voice_state_update(member: discord.Member, before: discord.VoiceState, after: discord.VoiceState) -> None:
    """Discord tells us every time ANYONE's voice state changes. We care about one person joining."""
    joined = before.channel is None and after.channel is not None
    if WATCH_USER_ID and member.id == WATCH_USER_ID and joined:
        owner = await bot.fetch_user(OWNER_ID)
        await owner.send(f"👀 **{member.display_name}** just joined **{after.channel.name}** in {member.guild.name}")

Restart the bot. Have your watched person hop into the General voice channel. Check your DMs.

This is event-driven architecture. You didn't write a loop that checks the voice channel every second. You registered interest in an event, and the system calls you when it happens. That's the whole idea, and it's the same shape as message queues, webhooks and UI click handlers.

3. Step 2: /due

Add a slash command due with an optional days argument (default 7). It should reply with await get_digest(CANVAS_FEED_URL, days), which already fetches and formats your Canvas feed (look in canvas.py). Find the STEP 2 comment.

Careful. Twenty bots share this server, and every one of them has a /due. Anyone could run yours. First line of the command: if interaction.user.id != OWNER_ID: return .... And never put str(e) in the reply: a connection error can echo the feed URL. Log it, reply with the error's name only.

Careful. Discord gives you 3 seconds to answer a slash command. Downloading the Canvas feed can take longer. So: await interaction.response.defer(ephemeral=True) first, then await interaction.followup.send(text, ephemeral=True).

Show me the code
@bot.tree.command(name="due", description="What's due on Canvas soon?")
@app_commands.describe(days="How many days ahead to look (default 7)")
async def due(interaction: discord.Interaction, days: app_commands.Range[int, 1, 60] = 7) -> None:
    # The server is shared; your Canvas data is not. Only answer the owner.
    if interaction.user.id != OWNER_ID:
        return await interaction.response.send_message("Not your bot — build your own! 🙂", ephemeral=True)
    await interaction.response.defer(ephemeral=True)
    try:
        text = await get_digest(CANVAS_FEED_URL, days)
    except Exception as e:  # bad URL, Canvas down, etc.
        log.exception("Canvas fetch failed")   # full detail stays in YOUR terminal...
        text = f"Couldn't read your Canvas feed ({type(e).__name__}). Check the terminal."  # ...never in chat
    await interaction.followup.send(f"📚 **Due in the next {days} days**\n{text}", ephemeral=True)

Restart, then /due. Try /due days:30. ephemeral=True means only you see the reply, so your deadlines aren't broadcast to the channel.

Calling an external API. canvas.py does a plain HTTPS GET to Canvas and parses the .ics file it gets back. No SDK, no token: the feed URL is the credential. Discord's REST API, which discord.py wraps for followup.send, is the same idea with more ceremony. Rate limits apply to both, which is what an API gateway enforces in front of any serious service.

4. Step 3: the morning digest

Three pieces, all at the STEP 3 comment: a send_digest() function that DMs you, a @tasks.loop that runs it at DIGEST_HOUR every day, and a /digest command that runs it right now so you don't have to wait until morning. Then start the loop in on_ready at STEP 3b.

Show me the code
@bot.tree.command(name="digest", description="Send me the morning digest right now")
async def digest_now(interaction: discord.Interaction) -> None:
    if interaction.user.id != OWNER_ID:
        return await interaction.response.send_message("Not your bot — build your own! 🙂", ephemeral=True)
    await interaction.response.defer(ephemeral=True)
    await send_digest()
    await interaction.followup.send("Sent — check your DMs.", ephemeral=True)


@tasks.loop(time=time(hour=DIGEST_HOUR, minute=0, tzinfo=TZ))
async def morning_digest() -> None:
    """Runs every day at DIGEST_HOUR. Only works if the bot is still running — hence deploying it."""
    await send_digest()


@morning_digest.before_loop
async def _wait() -> None:
    await bot.wait_until_ready()


async def send_digest(days: int = 7) -> None:
    owner = await bot.fetch_user(OWNER_ID)
    text = await get_digest(CANVAS_FEED_URL, days)
    await owner.send(f"☀️ **Good morning. Due in the next {days} days:**\n{text}")

And in on_ready, replace the STEP 3b comment with:

    if not morning_digest.is_running():
        morning_digest.start()

Restart, /digest, check your DMs. Tomorrow at 8 you'd get the same message. If the bot is still running.

Optional: remind me before it's due

Finished early, or doing this at home? The finished bot on main has one more feature: set REMIND_HOURS=24,1 in .env and it DMs you a day before and an hour before each deadline. Read reminders.py; it's short. The part worth your attention is the sent-list it saves to state/sent.json. Delete that file and restart, and you'll see why it exists.

Loop every 15 minutes, check which deadlines just entered a window, DM, remember. That's the whole thing. The remembering is the engineering.

5. Keep it running

Right now your bot dies when the Codespace sleeps or your laptop lid closes. A container packages your code, the exact Python, and the exact packages into one image that runs the same anywhere. The Dockerfile is already in the repo. Read it; it's nine lines.

docker build -t duebot .
docker run --env-file .env duebot

Secrets are passed in at run time with --env-file, never baked into the image. If you turned on reminders, add -v duebot-state:/app/state so the sent-list outlives the container.

Deploying it. Every host that runs Docker images (Railway, Fly, Render, Oracle Cloud, a Raspberry Pi) takes this same image. Push the repo, set the four environment variables in their dashboard, done. Free always-on hosting in 2026 is thin: Railway's one-time trial credit gets you live tonight, and Oracle Cloud's Always Free tier or your GitHub Student Pack credits are the long-term answers.

6. Watch: the other direction

Your bot opened a connection to Discord. A webhook is the mirror image: another service opens a connection to a URL you host. webhook_demo.py is a 60-line server that receives GitHub events (push, pull request) and relays them into a Discord channel. It needs a public URL, which on a laptop means a tunnel like ngrok. Watch the projector for this one, then try it at home with the steps at the top of the file.
